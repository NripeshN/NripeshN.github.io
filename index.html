CrossTL

Most GPU code gets written three times: once for CUDA, once for Metal, once for whatever ships next. CrossTL is a compiler so you write it once.

Every translation goes through CrossGL, a small intermediate language. A frontend imports GLSL, HLSL, Metal, CUDA or another source into CrossGL; a code generator writes CrossGL out as Metal, HLSL, SPIR-V, WGSL or another target. Adding a language means writing one frontend and one backend.

It fails closed

If CrossTL can't translate something, it stops with an error that names the construct and the target, instead of emitting a placeholder. Every push runs thousands of generated feature probes through it and checks the output with each language's own compiler or validator: glslang, DXC, spirv-val, naga, the Metal compiler, nvcc, hipcc, slangc, rust-gpu and the Mojo compiler. MetalFish

MetalFish is my chess engine. It's basically Stockfish's search on the CPU and an Lc0-style transformer search on the GPU, looking at the same position at the same time.

A UCI engine with three modes in one binary: CPU alpha-beta with NNUE (the strength), GPU Monte Carlo tree search with an Lc0-compatible BT4 transformer (the research path), and a hybrid that runs both on one position, exchanges root-level signals through lock-free shared state, and lets a coordinator pick the move. In practice the hybrid plays about as well as the alpha-beta half does on its own; the GPU side is a research and diagnostic path, not a strength multiplier. Metal and MPSGraph on Apple silicon, CUDA on NVIDIA, a CPU fallback with hand-written ARM NEON kernels. Prebuilt binaries for macOS arm64, Linux x86-64 and arm64, and Windows x86-64. GPL-3.0.

Measured on an M2 Max, October 2026, with the records in the repo: Metal transformer inference runs at 135 positions per second at batch 1 (FP16) and 538 at batch 64. The alpha-beta search does 1.53M nodes per second on one thread and 11.81M on eight (depth 16, five repeats).

What I want to work on next

  • Translating GPU programs between vendors without losing the source's rules: what a hub IR has to preserve, and how to test the result against each target's own toolchain. This is the CrossTL work.
  • Memory-safe GPU programs: a bounds-checking contract that survives translation, a differential oracle across targets, and the optimisations that make the checks cheap.
  • Compilation as a deployment policy: predicting what to compile next for programs you have never seen, and controlling speculative compilation online.
  • Hybrid search on unified-memory machines, where a CPU tree search and a GPU network search share one position.
